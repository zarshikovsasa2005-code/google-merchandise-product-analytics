# Продуктовая аналитика Google Merchandise Store

В этом проекте я анализировал поведение пользователей Google Merchandise Store на публичном датасете Google Analytics Sample.

Основная задача — пройти типичный цикл продуктового анализа: проверить качество данных, построить воронку, сравнить ключевые сегменты, оценить retention, проверить статистическую значимость различий и предложить дизайн эксперимента.

**Стек:** BigQuery SQL, Python, pandas, NumPy, Matplotlib, statsmodels

## Кратко о результатах

- Проанализировано **903 653 сессии** и **714 167 пользователей**.
- Общая конверсия сессии в покупку составила **1,28%**.
- Самый большой отвал внутри строгой последовательной воронки приходится на этап между просмотром товара и добавлением в корзину: **64,53%**.
- Конверсия в покупку на desktop составила **1,58%**, на mobile — **0,41%**.
- У returning users конверсия выше, чем у новых пользователей, на всех типах устройств.
- Referral дал около **46% всех покупок**, хотя на него пришлось только **11,6% сессий**.
- Weighted retention снизился с **3,39% в M1 до 1,09% в M2 и 0,58% в M3**.
- Для mobile product page подготовлен дизайн A/B-теста с user-level baseline и расчётом размера выборки.

## Проверка качества данных

Перед анализом я проверил уникальность сессий и отдельно разобрал случаи с повторяющимися идентификаторами.

Комбинация `fullVisitorId` и `visitId` повторяется для **898 пар**. При этом у каждой такой пары отличаются `visitStartTime` и дата.

После добавления `visitStartTime` составной ключ становится уникальным для всех **903 653 строк**. Поэтому эти записи не удалялись как дубликаты.

Для дальнейшего анализа сессия определяется комбинацией:

```text
fullVisitorId + visitId + visitStartTime
```

SQL-проверка находится в `sql/00_data_quality.sql`.

## Воронка

Для основной воронки использованы реальные ecommerce-события из `hits.eCommerceAction.action_type`.

Этапы:

1. все сессии;
2. просмотр товара;
3. добавление в корзину;
4. начало оформления;
5. покупка.

Воронка построена строго последовательно: каждый следующий этап учитывается только в том случае, если он произошёл после предыдущего по `hitNumber`.

| Этап | Сессии | Конверсия с предыдущего этапа |
|---|---:|---:|
| Все сессии | 903 653 | — |
| Просмотр товара | 124 188 | 13,74% |
| Добавление в корзину после просмотра | 44 044 | 35,47% |
| Checkout после корзины | 17 088 | 38,80% |
| Покупка после checkout | 9 072 | 53,09% |

Самый большой отвал внутри товарной части воронки наблюдается между просмотром товара и добавлением в корзину: **64,53%** сессий не переходят на следующий этап.

![Воронка](images/funnel_sequential.png)

### Почему в проекте есть две метрики покупки

В данных есть **11 552 сессии**, в которых зафиксировано событие покупки. Это соответствует общей observed purchase conversion **1,28%**.

При этом только **9 072 сессии** содержат полностью наблюдаемую последовательность всех этапов воронки. Доля таких сессий составляет **1,00%**.

Это разные показатели:

- 1,28% — бизнес-метрика наличия покупки в сессии;
- 1,00% — доля сессий, прошедших через всю строгую последовательность событий.

Я разделяю их, чтобы не смешивать итоговый бизнес-результат и аналитическое определение воронки.

## Сегментация по устройствам

По общей observed purchase conversion desktop заметно опережает mobile и tablet.

| Устройство | Сессии | Покупки | Конверсия в покупку |
|---|---:|---:|---:|
| Desktop | 664 479 | 10 528 | **1,58%** |
| Mobile | 208 725 | 856 | **0,41%** |
| Tablet | 30 449 | 168 | **0,55%** |

Desktop-конверсия примерно в **3,9 раза выше mobile**.

![Конверсия по устройствам](images/device_observed_purchase_conversion.png)

Само по себе это не доказывает проблему мобильного интерфейса. Разница может быть связана с намерением пользователей, каналом привлечения, составом аудитории и другими факторами. Поэтому я дополнительно посмотрел новые и возвращающиеся сессии.

## Новые и возвращающиеся пользователи

| Тип пользователя | Desktop | Mobile | Tablet |
|---|---:|---:|---:|
| New | 0,76% | 0,29% | 0,39% |
| Returning | 4,39% | 0,87% | 1,16% |

Returning users конвертируются заметно лучше новых пользователей на всех устройствах.

При этом разница между desktop и mobile сохраняется внутри обоих сегментов. Значит, её нельзя объяснить только тем, что на разных устройствах различается доля новых и возвращающихся пользователей.

![Новые и возвращающиеся пользователи](images/user_type_device_conversion.png)

| Канал | Доля трафика | Конверсия в покупку | Доля покупок |

| Organic Search | 42,22% | 0,90% | 29,80% |

| Direct | 15,83% | 1,44% | 17,84% |
| Referral | 11,60% | **5,08%** | **46,07%** |

| Affiliates | 1,82% | 0,05% | 0,08% |

Referral выделяется высоким качеством трафика: на канал приходится только **11,6% сессий**, но около **46% всех покупок**.

![Каналы привлечения](images/channel_efficiency.png)

По этим данным нельзя делать вывод о прибыльности каналов. Для оценки маркетинговой эффективности нужны расходы на привлечение, выручка и контекст рекламных кампаний.

## Когортный анализ и retention

Пользователи разбиты на когорты по месяцу первого наблюдаемого визита в доступном периоде.

Weighted retention:

- M1 — **3,39%**;
- M2 — **1,09%**;
- M3 — **0,58%**.

Retention первого месяца по отдельным когортам находится в диапазоне от **2,84% до 4,28%**.

![Когортный retention](images/cohort_retention_heatmap.png)

![Retention curve](images/retention_curve.png)

Основное наблюдение — пользователи быстро перестают возвращаться после первого месяца. Это делает раннее удержание отдельной зоной для дальнейшего исследования.

## Статистическое сравнение desktop и mobile

Для сравнения observed purchase conversion desktop и mobile использован two-proportion z-test.

Результаты:

- desktop CR — **1,584%**;
- mobile CR — **0,410%**;
- абсолютная разница — **1,174 п.п.**;
- отношение конверсий — примерно **3,86**;
- z-statistic — **41,26**;
- p-value — **< 0,001**;
- 95% доверительный интервал для разницы — примерно **[1,134; 1,215] п.п.**

Различие статистически значимо, но это **не A/B-тест**. Пользователи не распределялись случайным образом между типами устройств, поэтому результат показывает различие между сегментами, а не причинный эффект устройства.

## Дизайн эксперимента

В качестве кандидата для дальнейшей проверки я выбрал mobile product page, потому что на mobile особенно заметен отвал между просмотром товара и добавлением в корзину.

Возможная гипотеза: более заметная кнопка Add to cart и более простой выбор варианта товара повысят вероятность добавления товара в корзину.

Для расчёта baseline использован user-level подход:

- eligible users — **23 102**;
- converted users — **6 068**;
- baseline — **26,27%**.

Параметры примера эксперимента:

- randomization unit — пользователь;
- primary metric — доля пользователей, добавивших товар в корзину после первого eligible product view;
- MDE — **+5 п.п.**;
- alpha — **0,05**;
- power — **80%**;
- требуется около **1 285 пользователей на группу**;
- с запасом 10% — около **1 414 пользователей на группу**.

Подробное описание находится в `docs/experiment_design.md`.

## Ограничения

- Датасет публичный, исторический и обезличенный.
- Сегментные сравнения являются наблюдательными и не позволяют делать причинные выводы.
- Для самых ранних когорт реальный первый визит пользователя мог произойти до начала доступного периода.
- У когорт разная доступная длина наблюдения.
- Конверсия канала сама по себе не показывает ROI без данных о расходах и выручке.
- Раздел с A/B-тестом содержит только дизайн эксперимента; реального случайного разбиения в данных нет.
