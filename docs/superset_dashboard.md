# BI-дашборд Apache Superset — Google Merchandise Store

В дополнение к продуктовому исследованию построен интерактивный дашборд в **Apache Superset 6.0** с источником данных **Google BigQuery**. Дашборд работает в локальном Docker-окружении; адрес localhost не является общедоступной ссылкой.

## Архитектура

Публичный Google Analytics Sample (2016-08-01 — 2017-08-01) → BigQuery SQL-витрины → Superset Datasets → Charts → Dashboard.

Использованы три витрины в dataset `product_analytics`:
- `dashboard_sessions` — одна строка на сессию: дата, устройство, канал, пользователь, тип визита, факт покупки;
- `dashboard_funnel` — агрегированная **строгая последовательная** воронка по дате, устройству и каналу;
- `dashboard_retention` — месячные когорты первой наблюдаемой активности и доля активных пользователей M0–M11.

Воспроизводимые SQL-скрипты находятся в `sql/07_superset_sessions.sql`, `sql/08_superset_funnel.sql` и `sql/09_superset_retention.sql`.

## Метрики и результаты

| Показатель | Значение |
|---|---:|
| Сессий | 903 653 |
| Уникальных пользователей | 714 167 |
| Сессий с покупкой | 11 552 |
| Purchase CR | 1,28% |
| Просмотров товара в строгой воронке | 124 188 |
| Добавлений в корзину после просмотра | 44 044 |
| Переходов к checkout | 17 088 |
| Покупок после всех этапов | 9 072 |

Основная потеря в товарной воронке: **64,53% между просмотром товара и добавлением в корзину**. При этом 11 552 сессии с покупкой и 9 072 сессии, завершившие строгую воронку, — разные показатели: некоторые покупки не имеют полной наблюдаемой последовательности событий.

Другие срезы: desktop CR **1,58%**, mobile CR **0,41%**; Referral CR около **5,08%**. Статистика по устройствам и источникам является наблюдательной: различия нельзя интерпретировать как причинный эффект.

## Визуализации

- Четыре KPI: Sessions, Users, Purchase Sessions, Purchase CR.
- Динамика Purchase CR по дням.
- Purchase CR по устройствам и типу визита (New / Returning).
- Сессии и Purchase CR по каналам привлечения.
- Строгая последовательная воронка Product View → Add to Cart → Checkout → Purchase.
- Когортная тепловая карта Retention M1+.

Фильтры **Date Range**, **Device** и **Channel** пересчитывают графики, использующие сессионную витрину. **Retention намеренно исключён** из этих фильтров: он агрегирован на уровне когорт, и обычный фильтр даты/устройства может создать ложную интерпретацию. Воронка использует отдельный набор данных и не входит в текущий общий scope.

## Воспроизведение

1. Создать dataset `product_analytics` в BigQuery (регион `US`).
2. Выполнить SQL-файлы по порядку 07 → 08 → 09; таблица retention построена на `dashboard_sessions`.
3. Запустить локальный Apache Superset 6.0, установить драйвер `sqlalchemy-bigquery`.
4. Добавить подключение BigQuery через отдельную сервисную учётную запись с минимальными правами.
5. Зарегистрировать три датасета и построить диаграммы по перечисленным метрикам.

В целях безопасности **JSON-ключи сервисной учётной записи, пароли, настройки доступа и необработанный экспорт подключения Superset не хранятся в публичном репозитории**.

## Ограничения

- Данные исторические (2016–2017), публичные и обезличенные.
- Воронка использует `hitNumber` и последовательность ecommerce-событий; наблюдаемые покупки и полный путь — разные метрики.
- Когорты строятся по первому визиту в доступном периоде, а не по первой активности за всю жизнь.
- Для retention учитываются только полные месяцы до июля 2017 включительно. M0 исключён из тепловой карты, чтобы цветовая шкала отражала M1+.
- Локально опубликованный статус Superset Published **не делает дашборд доступным по внешней ссылке**.
